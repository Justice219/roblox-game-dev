# SellNukes world art — Blender → Roblox pipeline and the stud material

Owner rules this implements: **every model is built in Blender** (scripted `bpy`, never hand-placed
Studio parts) and **every world surface carries the stud texture**. The look target is the owner's
references (`docs/reference/missiles-vs-cities/*.png`, `docs/reference/sell-lemons/*.png`): chunky,
candy-coloured, LEGO-like toys with raised square studs on every face, chamfered edges, hazard
stripes and cartoon proportions.

## 1. The stud material decision (with evidence)

**Decision: one shared texture set exposed through `MaterialVariant`s** (`SNStuds`, `SNStudsSmall`,
`SNStudsLarge`). Any `BasePart` — primitive `Part` or Blender `MeshPart` — gets studs from
`Material = Plastic` + `MaterialVariant = "SNStuds"`, and its `Color` tints the near-white stud map.

### Experiment (Studio, edit mode, `tools/blender/studio/stud_experiment.luau`)

The same uploaded test meshes (`StudTest`: 4×4×4 chamfered cube + 3×4 cylinder, built by
`tools/blender/models/tests.py`) were placed next to primitive Parts of the same size, plus an 8×8×8
copy of the mesh (scaled 2×), with four application methods side by side:

| Method | Parts | MeshParts | Stud size on a 2× scaled mesh | Tint via `Color` | Extra instances / part | Runtime-scriptable maps |
|---|---|---|---|---|---|---|
| **MaterialVariant** (`stud-experiment-1-methods.jpg`, front row) | ✅ | ✅ | **unchanged (1 stud)** | ✅ | **0** | ❌ (PluginSecurity) |
| SurfaceAppearance (2nd row) | ❌ not supported | ✅ (UV) | **doubled** (stretches with scale) | via `SurfaceAppearance.Color` | +1 per MeshPart | ❌ |
| `Texture` ×6 (3rd row) | ✅ | ✅ (planar projection) | unchanged | `Color3` per Texture | **+6 per part**, one extra draw per face | ✅ |
| Legacy `SurfaceType.Studs` (back row) | ✅ | ❌ | n/a | ✅ | 0 | ✅ |

Two follow-up tests settled how MaterialVariants map onto meshes:

* `stud-experiment-2-studspertile4.jpg` — changing `StudsPerTile` 2 → 4 doubled the stud size on
  Parts **and** MeshParts identically (density is driven by the variant, not the mesh).
* `stud-experiment-3-uv-independent.jpg` — `StudTestUV2` (same geometry, UVs at **2× density**) shows
  exactly the same 4×4 studs per face as the normal-UV cube: **Roblox ignores mesh UVs for
  MaterialVariants** and projects in object space, compensating for MeshPart scaling.

**Why MaterialVariant wins:** it is the only method that works on both Parts and MeshParts with
identical, scale-proof stud density, tints through the ordinary `Color` property, adds **zero
instances** (hundreds of meshes on screen → no extra draw calls or replication) and keeps one texture
set in memory. SurfaceAppearance fails on Parts and stretches; Textures cost 6 instances + 6 extra
draws per part; legacy surfaces cannot touch MeshParts.

Consequences:

* Stud density is chosen per piece by **material name**, not by UVs: `Studs` (1 stud cells,
  `StudsPerTile = 2`), `StudsSmall` (½ stud cells, small props), `StudsLarge` (2 stud cells, huge far
  surfaces only). One mesh can be shown with any stud size.
* MaterialVariant map properties are **PluginSecurity** → game scripts cannot create a useful variant
  at runtime. The variants are authored instances in `src/server/World/StudMaterialVariants.model.json`
  (Rojo syncs them; it is generated by `tools/ui/upload_world_studs.py`) and
  `WorldMaterials.ensure()` **clones** them into `MaterialService` once at boot; MaterialService
  replicates them to every client.
* We still write world-scale cube-projected UVs in Blender (`snkit.export._cube_uv`): they keep
  tangent export valid, make the Blender previews show true stud size, and would let a
  SurfaceAppearance fallback work if Roblox ever changes the projection.

### The texture set (`tools/ui/build_world_studs.py` → `assets/world/studs/`)

512×512, a 2×2 grid of raised rounded-square studs (256 px per stud cell), fully periodic.

| File | Content |
|---|---|
| `studs_color.png` | near-white grey (gaps 0.86, tops 0.93) with soft baked bevel light from the top-left + contact shadow, so studs read even on low graphics quality |
| `studs_normal.png` | tangent-space normal map, OpenGL (+G up) as Roblox expects |
| `studs_roughness.png` | gaps 0.62, stud tops 0.48 (toy plastic sheen) |
| `texture.json` | size, cells per tile, sha256 per file (the uploader refuses mismatches) |

Uploaded Image ids live in `WorldMaterialConfig.Images` (generated block).

## 2. Pipeline: add a model → build → preview → upload → sync → spawn

```bash
# 0. (once / when the stud look changes) texture set + upload + variant model.json
python3 tools/ui/build_world_studs.py
python3 tools/ui/upload_world_studs.py --user-id 1586034782          # --dry-run validates offline

# 1. write a builder in tools/blender/models/<file>.py and register it in BUILDERS
# 2. build: FBX + GLB + previews + manifest (fails if a model is over its triangle budget)
/opt/homebrew/bin/blender -b --python tools/blender/generate_world.py -- --only MyModel
python3 tools/blender/contact_sheet.py --only MyModel        # LOOK at the previews
# 3. upload (Open Cloud Model) + recover MeshIds (asset-delivery + lune decoder)
python3 tools/blender/upload_meshes.py --user-id 1586034782 --only MyModel
# 4. regenerate src/shared/Config/MeshAssets.luau (Rojo syncs it)
python3 tools/blender/sync_meshes.py
lune run tests/mesh-assets                                    # parity + hash-bound ids
# 5. spawn in Studio (edit mode) and screenshot
python3 scripts/studio_mcp.py luau-file tools/blender/studio/spawn_area1_preview.luau
python3 tools/blender/studio_shot.py docs/verification/world-art/x.jpg --luau tools/blender/studio/camera.luau
python3 scripts/studio_mcp.py luau-file tools/blender/studio/cleanup_preview.luau   # ALWAYS clean up
```

`generate_world.py` with no `--only` rebuilds every model (≈2 s for 18 models). Geometry is
deterministic, so a rebuild without edits keeps every content hash and nothing re-uploads.

### Writing a builder (`tools/blender/models/*.py`)

```python
from snkit.core import Model, WOOD, DARK_STEEL, GLOW_GREEN
from snkit.kit import block, disc
from snkit.shapes import cylinder

def build_crate():
    m = Model("SupplyCrate", "ground centre; label faces -Z", budget=1500)
    body = m.piece("Body", WOOD)                                   # Studs material by default
    trim = m.piece("Trim", DARK_STEEL, material="StudsSmall")
    glow = m.piece("Glow", GLOW_GREEN, material="Neon")
    block(body, (0, 1.5, 0), (3, 3, 3), bevel=0.2)
    ...
    return m

BUILDERS = {"SupplyCrate": build_crate}
```

Every `tools/blender/models/<name>.py` (lower-case file name, except `__init__.py`) is
**auto-discovered** — create your own file, never edit a shared registry. A key defined in two
modules fails the build (`duplicate model key ...`). `models/tests.py` holds experiment-only
models that build only when named with `--only`.

Rules:

* **Roblox space everywhere**: studs, +Y up, model front = **−Z**, coordinates relative to the pivot.
  Write the pivot in the `Model(..., pivot)` string — it ships in `MeshAssets[key].pivot`.
* **One piece = one colour = one MeshPart = one draw call.** Put every same-colour detail in the same
  piece (`m.piece(name)` returns the existing piece). Target ≤ 12 pieces, hard cap 24.
* `tinted=True` marks pieces the caller recolours (`spawn(..., {tint = ...})`): pad tops, nuke tiers.
* Materials: `Studs` (default), `StudsSmall`, `StudsLarge`, `Smooth`, `Neon`, `Glass` (see §1).
* Hazard stripes are **geometry** (`hazard_band`, `hazard_floor`, `hazard_ring`) in separate
  `HazardYellow` / `HazardBlack` pieces, so they keep the stud material.
* Palette lives in `snkit/core.py` (candy colours; the stud map darkens them ~10 %).
* Piece names: `[A-Za-z][A-Za-z0-9_]*` (the uploader and extractor verify them).

### Upload, receipts and why nothing ships stale

* `upload_meshes.py` validates every FBX (binary header, size bound, sha256 == manifest
  `fbxSha256`, piece names/hashes) **before** reading the key.
* Upload identity = `contentHash` (sha256 over sorted `name:pieceHash`; piece hash covers vertices,
  triangles, UVs, colour, material, transparency) + creator. Same content → no network call. New
  content → new Model asset; the previous receipt moves to `_history` in `upload-receipts.json`.
* Journal `upload-operations.json` records intent **before** each POST and the operation **before**
  polling. An interrupted POST stays `submitting` and is never retried automatically: check Creator
  Dashboard, then rerun with `--abandon <Key>`.
* MeshIds come from downloading the owned model (`asset-delivery-api` → `*.rbxcdn.com`, no
  credentials on the CDN hop, bounded gzip) and decoding it as inert data with
  `lune run tools/blender/extract_meshes.luau` (aborts on any script; names must equal the manifest).
  Result: `mesh-ids.json` `{key: {contentHash, modelId, pieces: {name: {meshId, hash}}}}`.
* `sync_meshes.py` writes an id **only** when the receipt's `contentHash` equals the current manifest's
  and the piece hash matches; otherwise `id = 0` and MeshLibrary builds the primitive fallback.
  `--check` exits 1 when `MeshAssets.luau` is out of date.
* Key: `ROBLOX_OPEN_CLOUD_KEY` env var or `~/.config/robeasts/open-cloud.env` (mode 600, owned by
  you). Never on argv, never printed, never written. Creator: user `1586034782` (place owner).

## 3. Runtime

### `MeshLibrary` (`src/server/World/MeshLibrary.luau`)

```lua
MeshLibrary.preload(keys: {string}, priority?): (ready, failed)   -- yields; priority queue (default Plot)
MeshLibrary.spawn(modelKey, parent: Instance?, pivot: CFrame, opts: SpawnOptions?): Model
MeshLibrary.isUploaded(modelKey): boolean      MeshLibrary.has(modelKey): boolean
MeshLibrary.getBounds(modelKey): (CFrame, Vector3)   -- model-space box, for collision/trigger parts
MeshLibrary.stats(): {templates, coolingDown, inFlight}

SpawnOptions = { tint: Color3?, colors: {[pieceName]: Color3}?, name: string?, fallback: boolean?,
                 streamingMode: Enum.ModelStreamingMode?, castShadow: boolean? }
```

* One template MeshPart per MeshId (`AssetService:CreateMeshPartAsync`, `CollisionFidelity = Box`,
  `RenderFidelity = Automatic`), cached and cloned. Requests are de-duplicated, ≤ 6 in flight, 3
  attempts with backoff, failed ids cool down 60 s.
* Meshes are used only when **every** piece of the model loads; otherwise the whole model is the
  primitive fallback (same boxes, colours and stud material) — never a half-mesh model.
* Pieces: `Anchored`, `CanCollide/CanQuery/CanTouch = false`, `Massless`, no fluid forces. Collision
  is separate invisible primitives placed by PlotBuilder/HubBuilder (use `getBounds`).
* Model: `WorldPivot = pivot`, `ModelStreamingMode = Atomic` (default), attributes `MeshKey`,
  `MeshSource = "Mesh" | "Fallback"`, children in **bottom-to-top build order** (`MeshAssets[key].order`).
* `spawn` yields only while that key's templates are still loading → `preload` an area's keys first.
* Every piece gets a `BuildOrder` attribute (bottom-to-top, used by the client build-in). Pieces whose
  NAME resolves in `WorldFxConfig.Pieces` (`Rotor`, `Belt`, `Glow`, `Dish`, `Arm`, `Steam`, `Core`, ...)
  get the `WorldFx` tag and are animated by the client: **naming a Blender piece is all an art
  builder does to animate it** (see `docs/build-in.md` §4).
* Floor tiles: pass `castShadow = false` (flat, shadows wasted).

### Loading speed (owner R16: "the models took forever to load in")

- **Priority queue.** Up to **16** `CreateMeshPartAsync` requests run at once (was 6). Waiting
  requests are served most-urgent first:
  `MeshLibrary.Priority = { Now = 0, Hub = 1, Plot = 2, Background = 3, Idle = 4 }`. A queued
  request is promoted when a more urgent caller asks for the same mesh, so a purchase never waits
  behind the warm-up. Identical MeshIds are fetched once across all keys.
- **Boot warm-up.** It starts automatically when MeshLibrary loads in a running server, never in
  edit mode. The tiers come from `src/shared/World/PreloadList.luau`:
  1. hub + plot frame + locked-slot sign + BuyPad + all of Area 1 (`Hub` priority);
  2. areas 2–4 (`Background`);
  3. areas 5–10 (`Background`);
  4. everything else: pets, eggs, crates, attack, event (`Idle`).
- **`Workspace.WorldReady = true`** (plus `WorldReadySeconds`) is set once tier 1 is cached and no
  spawn is still waiting on a template. If that never settles, it is set after 20 s anyway.
- **`PlotReady`** goes on each plot model, set by B5's PlotBuilder after a restore has placed that
  player's bought builds. B5 restores area by area with
  `MeshLibrary.preload(PreloadList.areaKeys(area, owned), Priority.Plot)`, so far or unbought
  content never blocks.
- **Client loading screen:**
  `ContentProvider:PreloadAsync(PreloadList.forClient(profile.tycoon))` fetches the hub plus that
  plot's bought meshes.
- **Measuring.** `MeshLibrary.stats()` reports request latency (avg / p50 / p90 / max) and boot
  milestones (`tier1`–`tier4`, `worldReady`). `tools/qa/load_benchmark.py` compares new vs legacy
  loading in Studio; set `LegacyLoading = true` on the ModuleScript to get the pre-R16 behaviour.

### `WorldMaterials` (`src/server/World/WorldMaterials.luau`)

```lua
WorldMaterials.ensure(): boolean          -- clone SN* variants into MaterialService once (idempotent)
WorldMaterials.apply(part, "Studs")       -- Material + MaterialVariant from WorldMaterialConfig.Materials
WorldMaterials.studAll(root, "Studs"?)    -- dress every BasePart under root (skips Neon/Glass/ForceField)
```

Every primitive Part a level builder creates (big ground fields, collision you can see, fallback
blocks) should go through `apply` so it matches the meshes exactly.

| Class | Triangles / model | Notes |
|---|---|---|
| Ground tile (16×16) | ≤ 300 | current 44–220 |
| Small prop (pad, nuke, lamp, can) | ≤ 1,500 | current 656–1,400 |
| Building shell piece (wall, floor, door) | ≤ 1,500 | current 328–564 |
| Roof | ≤ 2,500 | current 804 |

| Hero landmark (later areas: silo, reactor dome) | ≤ 6,000 | |
| Any single piece | ≤ 10,000 | Roblox limit is 20k |
| Pieces per model | ≤ 12 target, 24 hard | each piece = 1 draw call |

`generate_world.py` fails the build when a budget is exceeded. The Area 1 preview scene (garage
shell, all props, 4 pads, 7 nukes, 37 tiles) = 177 MeshParts / ~26k triangles from 81 unique meshes,
all templates loaded in ~7 s cold in Studio.

For very large plain ground, prefer one big primitive Part with `WorldMaterials.apply(part, "Studs")`
over hundreds of tiles — identical stud density by construction (§1), far fewer instances.

## 6. Parallel art builders, locks and gotchas

### Running several builders at once

Each builder owns its own `tools/blender/models/<name>.py` and runs only its own keys:

```bash
/opt/homebrew/bin/blender -b --python tools/blender/generate_world.py -- --only KeyA,KeyB
python3 tools/blender/upload_meshes.py --user-id 1586034782 --only KeyA KeyB
python3 tools/blender/sync_meshes.py
```

This is safe to run concurrently with other builders:

| Shared state | Writer(s) | Protection |
|---|---|---|
| `assets/blender/world/manifest.json` | `generate_world.py` | builds run unlocked; then **`.sn-manifest.lock`** (blocking) → re-read manifest → replace only this run's keys → atomic fsync + rename. Over-budget models are never merged. |
| `src/shared/Config/MeshAssets.luau` | `sync_meshes.py` | whole read → render → write under **`.sn-manifest.lock`**, always regenerated from the full on-disk manifest + mesh-ids (temp file + rename), so the last sync reflects every builder |
| `upload-operations.json`, `upload-receipts.json`, `mesh-ids.json` | `upload_meshes.py` | one **`.sn-upload.lock`** turn per model (blocking); journal/receipts/mesh-ids re-read inside the lock, only that key replaced |
| `assets/world/studs/*` journal/receipts | `upload_world_studs.py` | `.sn-upload.lock` in that directory (blocking) |
| `<Key>.fbx/.glb`, previews | `generate_world.py` | per-key files; two builders never build the same key (duplicate guard) |

Locks are `fcntl.flock` advisory locks (`snkit.cloud.exclusive`, wait up to 30 min, polling 0.25 s,
prints `[lock] waiting for ...`). The kernel drops a lock when its holder dies, so a crashed builder
never wedges the rest. The `.sn-*.lock` files are empty markers and should be git-ignored.
Verified: two parallel `--only` builds plus a sync while a third process held the manifest lock all
waited, merged and kept every entry; the uploader waits on a held upload lock instead of failing.

### Gotchas

* **Studio edit camera**: set `camera.Focus` together with `CFrame` (edit cameras orbit their focus).
  `tools/blender/studio/camera.luau` does it.
* `scripts/studio_mcp.py` drops image blocks → use `tools/blender/studio_shot.py` for screenshots.
  If another agent is playtesting, `capture_screenshot` returns *their* play viewport: hold
  `python3 scripts/studio-lock.py acquire B4` while taking art screenshots.
* `solo_playtest stop` can time out while the server's BindToClose saves; retry with
  `{"action":"stop","timeout":60}`.
* Edit-mode previews clone the variants into MaterialService; **always** run `cleanup_preview.luau`
  so they are not saved into the place (Rojo's model.json is the source of truth).
* Images show "Reviewing" moderation right after upload; they still render for the owner in Studio.
* Blender stamps FBX files with a time, so FBX bytes change every build: identities use piece
  hashes, the FBX hash only binds the file to its manifest.
* MaterialVariant on a MeshPart ignores UVs — do **not** try to change stud size with UV scale;
  change the piece's material (`StudsSmall` / `StudsLarge`).
