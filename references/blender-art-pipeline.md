# Blender → Roblox art pipeline

Every 3D model in SellNukes is generated by a Python `bpy` script, built headless in Blender,
uploaded to Roblox through Open Cloud, and spawned at runtime as cloned MeshParts that carry one
shared stud material. Nothing is hand-modelled and nothing is hand-placed in Studio. This file
explains each tool in `tools/blender/` (and the icon, billboard and audio tools next to it), the
conventions every builder follows, the safety rules around uploads, the quality gates that catch
z-fighting and clipping, and the exact commands to add a new model. The pipeline started in the
RoBeasts repo (`~/IdeaProjects/RoBeasts/tools/blender`). The same pattern fits any Roblox game:
scripted builders → manifest → hash-bound upload → generated Luau registry → one template per mesh
id, cloned.

## 1. Why scripted Blender (owner rule 3)

The owner's first request (R1) was "Use Blender to model the entire tycoon, so it doesn't look
grey/primitive" and "Everything needs to be modeled in Blender though". The CLAUDE.md rule is:
**every model is built in Blender with scripted `bpy` builders, uploaded, and loaded as MeshParts;
primitive Parts are only the fallback while a mesh is not uploaded yet.**

Scripted builders, not hand modelling, because:

- **Deterministic.** The same script gives the same geometry, so content hashes are stable and an
  unchanged model is never uploaded twice.
- **Reviewable in git.** A model change is a code diff with a comment, not a binary blob.
- **Parallel.** Several agents can each own one `models/<file>.py` and build at once (§12).
- **Auditable.** The same builder code feeds the z-fight audit, the overlap checker and the
  budget gates, so a test can rebuild any model and inspect its real triangles.
- **Agent-friendly.** An agent cannot drag vertices, but it can write `block(body, (0, 1.5, 0),
  (3, 3, 3), bevel=0.2)`.

The fallback exists so the game never breaks. If an id is missing or a mesh fails to load,
`MeshLibrary` builds the same boxes, colours and stud material from the manifest. It never ships
half a mesh model.

## 3. snkit: the builder kit

Builders never call `bpy.ops` directly. They add geometry to a `Piece`'s bmesh through snkit
helpers, all in **Roblox space**. `core.rb()` converts a Roblox point `(x, y, z)` to Blender
`(x, -z, y)`. The FBX exporter (`axis_forward=-Z`, `axis_up=Y`) maps it back, so FBX space equals
Roblox space and you never think in Blender axes.

```python
from snkit.core import Model, WOOD, DARK_STEEL, GLOW_GREEN
from snkit.kit import block, disc
from snkit.shapes import cylinder

def build_crate():
    m = Model("SupplyCrate", "ground centre; label faces -Z", budget=1500)
    body = m.piece("Body", WOOD)                                   # "Studs" material by default
    trim = m.piece("Trim", DARK_STEEL, material="StudsSmall")
    glow = m.piece("Glow", GLOW_GREEN, material="Neon")            # name "Glow" => animated light
    block(body, (0, 1.5, 0), (3, 3, 3), bevel=0.2)
    ...
    return m

BUILDERS = {"SupplyCrate": build_crate}
```

A real one, `models/props.py` `build_buy_pad`: a `Tyre` piece (`tyre_ring`, 14 lugs), a `Rim`
piece (`revolve` of a 4-point profile), and a `Top` piece marked `tinted=True` so each pad can be
recoloured at spawn. Budget 1,500; actual 1,400 triangles.

## 4. Writing a builder

Follow these conventions. Most of them are enforced by `generate_world.py`, `upload_meshes.py` or
the lune tests.

### Space, scale, pivot

- **Units are studs, +Y up, model front = −Z**, and coordinates are relative to the pivot.
- **Write the pivot in the `Model(key, pivot, budget)` string.** It ships in
  `MeshAssets[key].pivot`, so level builders know how to place the model. Examples:
  `"ground centre of the pad; button top at y = 1.55"`,
  `"centre under the fins; nose up (+Y); badge faces -Z"`,
  `"garage origin: floor centre at ground, door toward -Z"`.
- The pivot is usually the **ground-contact centre** (pets: y = 0 under the middle).
- Pivot strings may carry **machine-parsable joints** for animation:
  `"...; hover 0.8; joints Head@(0,1.11,-0.11) Tail@(0,0.82,0.74)"`. The client parses them with
  `string.gmatch` (see `docs/pets-art.md` §1).
- Size to the avatar. Pets are 1.8–2.6 studs tall (R15 hip height), a pocket nuke is about 3, an
  area slot is 104 × 70 with an 80-stud height budget (140 for the finale area).

### Pieces = colours = MeshParts = draw calls

- **A MeshPart has one Color and one Material, so a model is split into single-colour pieces.**
  Each piece becomes one Blender object → one FBX mesh → one MeshPart → one draw call.
- **Merge every same-colour detail into the same piece.** `m.piece(name)` returns the existing
  piece when the name repeats.
- Aim for **≤ 12 pieces per model; 24 is the hard cap** (`MAX_PIECES`).
- **Name pieces `[A-Za-z][A-Za-z0-9_]*`.** The uploader and the extractor check this.
- **The piece name is also the animation contract.** A name that resolves in
  `WorldFxConfig.Pieces` (`Rotor`, `Belt`, `Glow`, `Dish`, `Arm`, `Steam`, `Core`, `Wheel`...)
  animates with no code; the leading capitalised word counts (`Rotor_Left` → Rotor). Pet groups
  use prefixes (`Head`, `Tail`, `WingL`, `Orbit`...), eggs use `ShellTop` / `ShellBottom`, crates
  use `Lid`, AA towers use `Turret` / `Barrel`, vehicles use `Tyres*`, `BrakeLights`,
  `IndicatorL/R` and `Cargo1..N`. So **decide what moves before you group by colour**: R75's miners
  were static because arm and pick shared the body's colour pieces.
- **Avoid accidental names.** There is deliberately no generic `Lava` or `Column` row; a static
  piece named `LavaCracks` would otherwise start moving.
- `tinted=True` marks a piece the caller recolours at spawn (`opts.tint` / `opts.colors`): pad
  tops, nuke tier colours, plot-coloured paths.

### Materials (resolved at runtime by `WorldMaterialConfig`)

| Name | Use | Studs? |
|---|---|---|
| `Studs` (default) | walls, machines, floors | 1-stud cells |
| `StudsSmall` | small props: nukes, pets, eggs, tools | ½-stud cells |
| `StudsLarge` | huge far surfaces only (sea, ground fields) | 2-stud cells |
| `Smooth` | NPC skin and faces (studs on skin read as dirt), tiny details, lettering | no |
| `Neon` | small glowing accents: bulbs, cores, eyes | no |
| `Glass` | windows, domes, slime, bubble helmets (set `transparency`) | no |

- **Stud density comes from the material, not UVs** (§10). To change stud size, change the
  material. UV scale does nothing.
- **Hazard stripes are geometry** (`hazard_band`, `hazard_floor`, `hazard_ring`) in separate
  `HazardYellow` / `HazardBlack` pieces, so they keep the stud texture.
- **Keep Neon small.** A Neon piece whose largest box face is over 6 studs² renders as bright
  SmoothPlastic (`MeshPlacement.resolveGlow`, owner R19). Split real accents out, or author big
  glows as `Smooth` in a light colour.

### Colours

Use the palette constants in `snkit/core.py`: `WHITE`, `GRASS`, `ROAD`, `HAZARD_YELLOW`,
`TOY_RED`, `GLOW_GREEN`, `WOOD`, `DARK_STEEL` and so on. Never use inline RGB tuples, so every area
matches. The stud colour map is 0.86–0.93 grey, so **on-screen colour is about 10 % darker than
authored**. The palette is already brightened for that. See `world-art-and-build-in.md` for the
look.

### Triangle budgets (`docs/world-art.md` §4)

| Class | Triangles per model |
|---|---|
| Ground tile 16×16 | ≤ 300 |
| Small prop (pad, nuke, lamp) | ≤ 1,500 |
| Building shell piece | ≤ 1,500 |
| Roof | ≤ 2,500 |
| Machine / furniture | ≤ 3,000 |
| Pet | ≤ 2,800 (≤ 10 pieces) |
| Hero landmark | ≤ 6,000 (also the per-placed-model cap in `tests/mesh-assets.luau`) |
| Any single piece | ≤ 10,000 (Roblox's limit is 20k) |
| Fully built area | main 36k / finale 42k; Dino 28k / finale 34k |

Pass `budget=` to `Model`; the build **fails** when a model exceeds it. Cheap tricks that worked:

- unbevelled block letters (12 triangles instead of 44);
- 16-triangle Neon gem bulbs;
- an 84-triangle `tiny_nuke` for crate filler;
- **one mesh placed many times** for repeated props (fence runs, lamps, scooters), so Roblox
  instances it.

### Determinism

No `random` without a fixed seed. Icon rocks use a hash function (`_hash01`), not an RNG. A
deterministic builder keeps every piece hash on rebuild, so nothing re-uploads.

### Text

Lettering is geometry (`block_text`, a 5×7 brick-pixel font in `models/area01.py`). **Text on a
−Z face must advance toward −X** or it reads mirrored from the road. **Signs are double-sided**: the
back copy is the 180° yaw of the front about the board centre (owner R17).

## 5. Build: generate_world.py

```bash
# everything (deterministic; ~2 s per 18 models)
/opt/homebrew/bin/blender -b --python tools/blender/generate_world.py
# only your keys (the normal case)
/opt/homebrew/bin/blender -b --python tools/blender/generate_world.py -- --only BuyPad,PocketNuke
# flags after `--`: --only K1,K2  --out DIR  --previews DIR  --no-previews
```

For each model, it does the following:

1. `reset_scene()` (empty factory scene) and calls the builder.
2. `realize` each piece:
   - recalculates outward normals;
   - writes world-scale cube-projected UVs (`UV_STUDS = 2` studs per UV unit);
   - marks sharp edges where faces meet at more than 35° (crisp chamfers, smooth cylinders);
   - triangulates, so triangle counts are exact.
3. Checks the budget, `MAX_PIECES = 24` and `MAX_PIECE_TRIANGLES = 10_000`. Over budget means the
   model is not merged.
4. Exports **binary FBX** (forward −Z, up Y, tangent space on) and a **GLB**. The GLB is what the
   lune z-fight audit reads for real triangles.
5. Renders Workbench previews `<Key>_front.jpg` and `<Key>_iso.jpg` with the stud texture tinted
   per piece.
6. Merges only this run's keys into `manifest.json` under `.sn-manifest.lock` (atomic write).

Manifest entry per key: `pivot`, `budget`, `triangles`, `fbxSha256`, and `pieces[]` with `name`,
`size`, `offset` (the box relative to the pivot, Roblox axes), `color`, `material`, `tinted`,
`transparency`, `triangles` and `hash`. **The piece hash covers vertices, triangles, UVs, colour,
material and transparency, not FBX bytes**, because Blender time-stamps FBX files.

## 6. Review: previews, contact sheets, Studio shots

**Look at every model before you upload it.** Agents that skipped this shipped mirrored text,
floating caps and roofs shifted half a hall sideways.

```bash
python3 tools/blender/contact_sheet.py --only MyModel            # -> assets/blender/previews/_sheet_iso.jpg
python3 tools/blender/contact_sheet.py --view front --only A,B   # road view: check lettering
/opt/homebrew/bin/blender -b --python tools/blender/viewport_look.py -- /tmp/vp Shop_X,Shop_Y \
    tools/blender/models/shop_props.py                            # colour as a shop ViewportFrame shows it
```

- Read the JPGs with the Read tool. Check silhouette, colour, text direction, and that parts sit
  on their bodies.
- **Workbench previews show authored colours at about half brightness**, so yellows look olive.
  Use `viewport_look.py` to judge colour (owner R47 "washed out"). It also accepts a `git show`
  copy of an older module for before/after pairs.
- **Studio verification is the lead's job, once, at the end** (owner R92: parallel builders code
  and test only; R132: no playtests for small changes). Edit-mode preview spawners stage an area
  far from the play space. Always clean up, because the preview clones MaterialVariants into
  MaterialService, and the place must not save them:

```bash
python3 scripts/studio-lock.py acquire <name>                       # one Studio user at a time
python3 scripts/studio_mcp.py luau-file tools/blender/studio/spawn_area01.luau   # STAGE = k, SHOW_COLLISION = true
python3 tools/blender/studio_shot.py docs/verification/world-art/x.jpg --luau tools/blender/studio/camera.luau
python3 scripts/studio_mcp.py luau-file tools/blender/studio/cleanup_preview.luau  # ALWAYS
python3 scripts/studio-lock.py release <name>
```

## 7. Upload: upload_meshes.py and Open Cloud

```bash
python3 tools/blender/upload_meshes.py --user-id <creator-user-id> --only MyModel OtherModel   # space separated
python3 tools/blender/upload_meshes.py --user-id <creator-user-id> --dry-run                   # validate offline
python3 tools/blender/upload_meshes.py --user-id <creator-user-id> --abandon MyModel           # after a stuck POST
```

The creator is the user that owns the place (the id is recorded in `docs/world-art.md`). Assets
must belong to the place's creator, or `CreateMeshPartAsync` cannot load them.

**Credentials.** The Open Cloud API key is read from the `ROBLOX_OPEN_CLOUD_KEY` environment
variable, or from a private env file you own with mode 600 (`~/.config/robeasts/open-cloud.env`,
one `ROBLOX_OPEN_CLOUD_KEY=` line). The icon tool also accepts the robloxstudio-mcp key file under
`~/.config/robloxstudio-mcp/`. The key is **never accepted on argv, never printed, never written
to a file or log**. The validator reads it only after every local file has passed validation.

**Step by step:**

1. **Validate locally first:**
   - the FBX is a regular file with a binary header and is under 20 MB;
   - its sha256 equals the manifest's `fbxSha256`;
   - piece names and hashes match the manifest.
2. **Upload identity = (contentHash, creator).** contentHash = sha256 over the model's sorted
   `name:pieceHash` pairs.
   - Same content → no network call.
   - Changed content → a new Model asset; the old receipt moves to `_history` in
     `upload-receipts.json`.
3. **Journal before every POST.** `upload-operations.json` records the intent, then the operation
   path, before polling.
   - An interrupted POST stays `submitting` and is **never retried automatically**: it may have
     created an asset.
   - Check Creator Dashboard, then rerun with `--abandon <Key>`.
4. **Recover MeshIds.** Download the owned model (Open Cloud asset delivery → a `*.rbxcdn.com`
   hop with no credentials, bounded gzip), then decode it as **inert data** with
   `lune run tools/blender/extract_meshes.luau <model> <out.json>`. It aborts on any script, and
   piece names must equal the manifest's.
   - Result: `mesh-ids.json` = `{key: {contentHash, modelId, pieces: {name: {meshId, hash}}}}`.
5. **Transport hardening** (`snkit/cloud.py`): fixed host, verified TLS, no proxies, no
   redirects, bounded responses, and remote error bodies are never echoed.

**The Studio MCP `upload_asset` tool** (`python3 scripts/studio_mcp.py call upload_asset ...`) also
uploads through Open Cloud. Use it for one-off assets such as a decal or a test image. For world
meshes, always use `upload_meshes.py`: only it writes the journal, the hash-bound receipts and the
MeshId extraction that `sync_meshes.py` depends on.

New uploads show "Reviewing" moderation at first; they still render for the owner in Studio.

## 8. Sync: MeshAssets.luau

```bash
python3 tools/blender/sync_meshes.py            # regenerate src/shared/Config/MeshAssets.luau
python3 tools/blender/sync_meshes.py --check    # exit 1 if stale (CI)
lune run tests/mesh-assets                      # parity + hash-bound ids
```

`MeshAssets.luau` is **generated, never hand-edited**. It has about 500 models in 41k lines.

```lua
MeshAssets.BuyPad = {
	pivot = "ground centre of the pad; button top at y = 1.55",
	triangles = 1400,
	order = { "Tyre", "Rim", "Top" },                 -- bottom-to-top: the build-in drop order
	pieces = {
		Rim = { id = 125634818104800, size = Vector3.new(4.84, 1.07, 4.84),
		        offset = Vector3.new(0, 0.685, 0), color = Color3.fromRGB(92, 98, 112),
		        material = "Studs", tinted = false, transparency = 0 },
		...
```

**Why a stale mesh can never ship:** a piece gets its id only when the receipt's contentHash equals
the **current** manifest's and the piece hash matches. If you rebuild without re-uploading, every
id of that model becomes `0`, and MeshLibrary draws the correct-size primitive fallback instead of
an outdated mesh. `order` sorts pieces by the bottom of their box, then by name.

## 9. Runtime: MeshLibrary, one template per mesh id

`src/server/World/MeshLibrary.luau` (server):

```lua
MeshLibrary.preload(keys, priority?)                 -- yields; priority queue
MeshLibrary.spawn(modelKey, parent, pivot: CFrame, opts?) -> Model
MeshLibrary.getBounds(modelKey) -> (CFrame, Vector3) -- for collision / trigger boxes
-- opts: tint, colors {[piece]=Color3}, name, fallback, streamingMode, castShadow
```

- **One template MeshPart per MeshId** (`AssetService:CreateMeshPartAsync`,
  `CollisionFidelity = Box`, `RenderFidelity = Automatic`). Templates are cached and every spawn
  clones them.
  - Requests are de-duplicated across keys.
  - Up to 16 run at once, served by priority `Now 0 < Hub 1 < Plot 2 < Background 3 < Idle 4`. A
    queued request is promoted when a more urgent caller asks for it.
  - 3 attempts with backoff; a failed id cools down for 60 s.
- **All pieces or none.** A model uses meshes only when every piece loaded; otherwise the whole
  model is the primitive fallback. Never half a mesh model.
- **The import yaw fix.** Roblox's FBX import bakes a 180° yaw into vertices: pieces land at
  `(-x, y, -z)` of their offset. Mesh pieces are placed with
  `pivot * CFrame.new(offset) * MeshPlacement.ImportYaw` (`CFrame.Angles(0, math.pi, 0)`).
  Fallback boxes skip it. This one bug caused mirrored text (R17), the hedge through the garage
  (R24) and caps floating beside nuke bodies (R26).
- **Meshes are visual only.** Pieces are `Anchored`, `CanCollide`, `CanQuery` and `CanTouch` false,
  `Massless`. Collision is separate invisible primitive boxes from the layout. Every piece gets a
  `BuildOrder` attribute; animated pieces get the `WorldFx` tag. The model gets `MeshKey` and
  `MeshSource = "Mesh" | "Fallback"`, and `ModelStreamingMode = Atomic`.
- **Glow and material.** `MeshPlacement.resolveGlow` swaps big Neon for SmoothPlastic, then
  `WorldMaterials.apply(part, name)` sets Material + MaterialVariant.
- **Boot warm-up tiers** (`src/shared/World/PreloadList.luau`):
  1. hub + plot frame + BuyPad + area 1 (Hub priority), then `Workspace.WorldReady = true`;
  2. areas 2–4;
  3. areas 5–10;
  4. pets, eggs, crates, attack (Idle).

  On the client, the loading screen preloads a critical list (87 mesh ids for a new player) and
  defers the rest.

## 10. The stud material

**Decision: one shared texture set exposed as MaterialVariants `SNStuds`, `SNStudsSmall` and
`SNStudsLarge`.** Any BasePart gets studs from `Material = Plastic` + `MaterialVariant = "SNStuds"`,
and its `Color` tints the near-white map. This was settled by an experiment in Studio
(`studio/stud_experiment.luau`; evidence in `docs/verification/world-art/stud-experiment-*.jpg`):

| Method | Parts | MeshParts | Scale-proof | Extra instances |
|---|---|---|---|---|
| **MaterialVariant** | yes | yes | **yes** (object-space projection, ignores UVs) | **0** |
| SurfaceAppearance | no | yes (UVs) | no, stretches | +1 per MeshPart |
| `Texture` × 6 | yes | yes | yes | +6 per part, +6 draws |
| `SurfaceType.Studs` | yes | no | n/a | 0 |

- MaterialVariant map properties are **PluginSecurity**, so game scripts cannot build a variant.
  The variants are authored as `src/server/World/StudMaterialVariants.model.json`, which is
  generated and synced by Rojo. At boot, `WorldMaterials.ensure()` clones them into
  MaterialService once.
- Texture set: `tools/ui/build_world_studs.py` → `assets/world/studs/`:
  - 512 × 512, a 2 × 2 grid of rounded-square studs;
  - `studs_color.png` is near-white with a soft baked bevel, so studs read on low graphics;
  - `studs_normal.png` is OpenGL +G;
  - `studs_roughness.png` makes stud tops glossier than the gaps;
  - `texture.json` holds a sha256 per file.

  Upload with `tools/ui/upload_world_studs.py`; it also regenerates the `WorldMaterialConfig.Images`
  block and the variant model.json.
- Primitive Parts that level builders create (big ground fields, fallback blocks) go through
  `WorldMaterials.apply(part, "Studs")` so they match the meshes exactly. For huge plain ground,
  one big studded Part beats hundreds of tiles.

## 11. Quality gates: z-fight, overlaps, glow, budgets

All of these run in `./scripts/check.sh` (lune) or headless Blender. They cover **every world** by
iterating `WorldsConfig.Order` through `tests/fixtures/ArtWorlds.luau`.

| Gate | Command | Catches |
|---|---|---|
| Mesh registry | `lune run tests/mesh-assets` | shape, manifest parity, hash-bound ids, ≤ 24 pieces, every placed key uploaded (no id 0 = no grey boxes), ≤ 6k triangles per placed model, per-area triangle budget |
| Z-fighting (owner R18) | `lune run tests/zfight-audit.luau` (`LUNE_VERBOSE=1` lists offenders) | coplanar, same-facing, overlapping faces from **real GLB triangles**; curved same-height seams that flicker at LOD range (R18b); fallback-box pairs on road models |
| Interpenetration (owner R24) | `/opt/homebrew/bin/blender -b --python tools/blender/check_area_overlaps.py -- 1 2 3` (`--world dino 1 2 3 4 5 6`, `--verbose`) | visible pieces of different models clipping more than 0.2 studs. Island boxes are only candidates; every hit is confirmed on triangles via `BVHTree`, so a prop inside a hollow shell passes and a hedge through a wall fails. Intended overlaps go in `ALLOWED` with a reason. |
| Glow (owner R19) | `lune run tests/glow-budget` | `LightCaps` brightness ≤ 0.6, range ≤ 10, pulse ≤ 0.2; Neon > 6 studs² rendered as Smooth; ≤ 32 studs² of rendered Neon and ≤ 24 Neon pieces per fully built area; no Neon primitive blocks |
| Billboard clearance (R31/R32) | `lune run tests/billboard-clearance` | producer billboards inside geometry; stale `BillboardSpots.luau` |
| Area layouts | `lune run tests/area-layouts` | keys, CFrames and collision inside the slot; strict `LayoutLogic.validate` |

- The z-fight audit used to have a **per-owner ratchet** (`PENDING`): counts could only go down.
  Every owner is now at 0 and the audit asserts 0, so any new offender fails the suite.
- The z-fight layer rule (which heights floors, rugs and decals use) is in
  `world-art-and-build-in.md`.

## 12. Running several art builders at once

Each builder owns its own `models/<name>.py` and runs only its own `--only` keys. Shared files are
protected by `fcntl.flock` advisory locks (`snkit.cloud.exclusive`). They wait up to 30 min, poll
every 0.25 s, and print `[lock] waiting for ...`. The kernel drops a dead holder's lock.

| Shared state | Writer | Protection |
|---|---|---|
| `manifest.json` | `generate_world.py` | build unlocked → `.sn-manifest.lock` → re-read → replace only this run's keys → fsync + rename |
| `MeshAssets.luau` | `sync_meshes.py` | same lock; always regenerated from the full manifest + mesh-ids |
| journal, receipts, `mesh-ids.json` | `upload_meshes.py` | one `.sn-upload.lock` turn per model; re-read inside the lock |
| `<Key>.fbx/.glb`, previews | `generate_world.py` | per-key files; a key defined in two modules fails the build |

**Never edit a shared registry to add a model.** Discovery is automatic, which is what makes
parallel art builders safe. The `.sn-*.lock` files are empty markers; keep them git-ignored.

## 13. 3D UI icons and brand renders

Owner R9: icons must look "rendered instead of flat". The pipeline is `docs/icons.md`, driven by
`tools/ui/icons/icons.py` (it was ported from RoBeasts' HUD icon tooling). There are 122+ keys.

- **Sources** are catalogued in `assets/icons/sources.json`, which records a `why` for each choice:
  - **pack**: Microsoft Fluent Emoji 3D (MIT), pinned by URL + sha256 and committed;
  - **blender**: `tools/blender/ui_icons/render_icons.py` `BUILDERS`, for anything the pack lacks
    (the pocket nuke, calendar, prize wheel, world currencies);
  - **composite**: layered pack and Blender parts. Part names start with `_`.
- **One shared look:**
  - a soft-toon emission material (eased 3-tone ramp, violet shadow → base → warm light,
    facing-ratio edge darkening, a white specular blob);
  - one sun light high front-left with no cast shadows;
  - an orthographic 3/4 camera (yaw 28°, pitch 20°);
  - thin inverted-hull inner lines.

  Post-processing, identical for every source, re-fits the art to 464 px of a 512 canvas, adds an
  exact disc-dilation outline (18 px) and a 4:1 premultiplied downsample.
- **Lesson:** never use Solidify `use_even_offset` for inverted hulls. It spikes into black shards
  on thin parts.
- **Kid rules in icons:** no skulls on bones, no insects in amber, dino heads without teeth or
  claws.
- **Legibility (R11):** check `assets/icons/contact-sheet-small.png` at 40, 56 and 96 px. Every
  icon must keep a distinct silhouette on a phone and on a TV.
- **Runtime:** `IconAssets.get(key)` / `IconAssets.image(key)` (generated). An empty `image` falls
  back to flat glyphs.

```bash
python3 tools/ui/icons/icons.py render --only Key     # Blender pass (~3 s per icon) + outline + sheets
open assets/icons/contact-sheet.png assets/icons/contact-sheet-small.png   # owner R12: look at it
python3 tools/ui/icons/icons.py upload --user-id <creator-user-id> --only Key [--replace Key]
python3 tools/ui/icons/icons.py moderation && python3 tools/ui/icons/icons.py sync
```

Blender icon renders run with `blender --background --factory-startup --python-exit-code 1 --python
tools/blender/ui_icons/render_icons.py -- <out_dir> [Name ...]`. `render_brand.py` renders the
logo, the mascot and the hub key art from the real world GLBs; `tools/ui/brand/brand.py` composes
and uploads them into `BrandAssets.luau`. The Moon skybox is built and uploaded by
`tools/ui/sky/moon_sky.py`, with the same journal and receipt pattern.

## 14. Billboard spots and audio

**Billboard spots** (`tools/billboards/generate-spots.luau`) are part of the asset pipeline
because they depend on meshes and layouts.

- It solves every area's producer billboard spot offline, using the same pure code as the client
  (`BillboardPlacement`), and writes `src/shared/Config/BillboardSpots.luau`. The client then
  places billboards with a table lookup, at zero solve cost on join.
- Re-run it after any layout, mesh or placement change: `lune run
  tools/billboards/generate-spots.luau [--world dino]`. `tests/billboard-clearance.luau` fails
  while the table is stale.

**Audio** (`docs/audio.md`) uses the same journaled-upload pattern through `snkit.cloud`.

- SFX are **original and synthesised**: `tools/audio/generate_world_sfx.py` and
  `generate_game_sfx.py` render numpy → WAV → MP3 with fixed seeds, so output is byte-identical on
  re-run.
- A few picked ForgeGUI takes go through `forge_manifest.py`.
- `python3 tools/audio/upload_sfx.py --user-id <creator-user-id> [--set world game]` uploads and
  regenerates the `SFX_IDS` block of `SoundAssets.luau`.
- Music comes only from Roblox-licensed APM tracks, recorded with their ids in `SoundAssets.luau`.
- Systems call `Sound.play(key)`; they never create Sound instances. Build-in sounds (`clack`,
  `whoosh`, `sparkle`, `kaching`, `pop`, `fanfare`) play through the `FxSound` adapter.

## 15. Add a new model, end to end

1. **Decide the contract.** Key (area models use `A<N>_Name`, Dino `D<N>_`, Moon `M<N>_`),
   pivot, front direction, what animates (piece names), what is tinted, and the budget class (§4).
2. **Write the builder** in your own `tools/blender/models/<file>.py` (or append to the module
   you own). Export `BUILDERS = {"MyModel": build_my_model}`. Use palette constants and snkit
   helpers, and keep it ≤ 12 pieces. Comment the pivot and any non-obvious maths.
3. **Build:**
   `/opt/homebrew/bin/blender -b --python tools/blender/generate_world.py -- --only MyModel`
   The build fails on budget, piece count or a duplicate key.
4. **Look:** `python3 tools/blender/contact_sheet.py --only MyModel` (and `--view front` for
   lettering), then Read the JPG. For colour-critical props, run `viewport_look.py`. Fix and
   rebuild until it is right.
5. **Upload:**
   `python3 tools/blender/upload_meshes.py --user-id <creator-user-id> --only MyModel`
6. **Sync:** `python3 tools/blender/sync_meshes.py && lune run tests/mesh-assets`
7. **Place it.** Add a placement to the area layout (`AreaLayouts/AreaNN.luau`, `HubLayout.luau`
   or a world's `Layouts/`) with explicit invisible collision boxes (`MeshLibrary.getBounds`
   helps), or spawn it from code with `MeshLibrary.spawn(key, parent, pivot, opts)`.
8. **Animate (optional).** Add or reuse a `WorldFxConfig.Pieces` row or an `Assemblies[key]`
   entry. Vehicles also get a `VehicleRouteConfig` route.
9. **Gate:**
   - `lune run tests/zfight-audit.luau`
   - `/opt/homebrew/bin/blender -b --python tools/blender/check_area_overlaps.py -- <areas>`
   - `lune run tests/glow-budget`
   - if it sits near a producer: `lune run tools/billboards/generate-spots.luau`
   - finally `./scripts/check.sh`
10. **Document.** Add the model to the area section in `docs/areas-art.md` (append-only, your own
    section): pieces, triangles and placement. Record owner feedback in `docs/owner-requests.md`.
11. **Commit** the builder, manifest, receipts, mesh-ids, `MeshAssets.luau`, previews and docs
    together. In a shared tree, commit only your hunks.
12. **Studio.** List what the lead should eyeball in their single Studio pass. Do not playtest
    yourself unless you are the lead holding the studio lock.

## 16. Gotchas

- **Don't change stud size with UVs.** MaterialVariant on a MeshPart ignores them; change the
  piece material.
- **`prism()` extrudes symmetrically.** An outline authored off-centre once shifted a roof half a
  hall sideways (A10_TurbineHall).
- **One big piece box can hide placement bugs.** `A1_Yard`'s `Hedges` piece spanned three hedge
  rows, so the yaw bug threw the back row through the garage. Split big pieces left/right
  (`HedgesL/R`) when that also helps billboard clearance.
- **Edit-camera framing.** Set `camera.Focus` together with `CFrame`; edit cameras orbit their
  focus.
- **Screenshots.** `scripts/studio_mcp.py` drops images, so use `studio_shot.py`. If another agent
  is playtesting, `capture_screenshot` returns *their* viewport: hold the studio lock.
- **FBX bytes change every build.** Never key anything on the FBX hash except binding the file to
  its manifest.
- **HubBuilder falls back to the placeholder hub if any HubLayout key is missing from
  MeshAssets.** Build and sync new hub keys **before** referencing them.
- **Never open the `.rbxlx` that `rojo build` produces** (owner R33). Use only the already-open
  MCP-connected place.

## 17. Porting the pipeline to a new game

Carry these over unchanged; they are game-agnostic:

1. `snkit/` (rename it; change only the palette in `core.py`) and the `models/` auto-discovery
   with `BUILDERS` dicts and duplicate-key failure.
2. `generate_world.py`: budgets, piece cap, manifest merge under a lock, FBX + GLB + previews.
3. `snkit/cloud.py` + `upload_meshes.py` + `extract_meshes.luau`: hash-identity, journal before
   POST, no automatic retry of ambiguous POSTs, inert extraction, key only from env or a 600 file.
4. `sync_meshes.py` → a generated `MeshAssets` module whose ids are bound to the current content
   hash.
5. A server `MeshLibrary`: one template per id, cloned; priority preload; all-or-nothing
   fallback; the 180° import-yaw correction; visual-only pieces plus explicit collision.
6. One stud (or other signature) MaterialVariant set authored as a Rojo model and cloned into
   MaterialService.
7. The gates: mesh-registry parity, the z-fight audit on GLB triangles, the Blender overlap
   checker, the glow budget.

Then decide the game's look (palette, materials, budgets) and write it down before the first
builder, as `docs/world-art.md` does.
